# Expo

**Ship a tested mobile feature with the right update path**

Build an Expo feature, verify it on its target platform, and choose the correct build or update workflow.

**Works well with:** Software Engineer, Product Interface Designer, Infrastructure Reliability Engineer, Adversarial Verifier.

## What to bring

- Feature and user flow
- Project and SDK version
- Build or update destination

## Setup

1. Open the Expo project, record its SDK and dependencies, and select the target device or simulator.

**Access:** Local tools; EAS and store services use their plans.

## Supported functions

| Function | Use it to |
| --- | --- |
| `expo-overview` | Choose the appropriate Expo workflow |
| `expo-native-ui` | Build the mobile interface |
| `expo-dev-client` | Prepare the development client |
| `eas-update` | Choose and verify the appropriate application update |

## Workflow

1. Inspect navigation, native dependencies, and the development-client requirements.
2. Implement the feature using the project’s data and UI patterns.
3. Run component checks and the target-device walkthrough.
4. Choose the matching build or update route and verify the resulting artifact or preview.

## What you get

- Working mobile feature
- Device test results
- Build or update artifact

## Check the result

- The target user flow works on the selected platform.
- The distribution method matches the native dependency changes.
