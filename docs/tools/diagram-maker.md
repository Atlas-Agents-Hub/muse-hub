# Diagram Maker

**Choose the diagram that explains the system**

Represent system structure or behavior with an appropriate diagram and consistent labels.

**Works well with:** Data Engineering Architect, Software Engineer, Product Interface Designer, Research Evaluator, Coordinator.

## What to bring

- Source material
- Question to answer
- Required notation and format

## Setup

1. Provide the source architecture, schema, interactions, or data that the diagram must explain.

**Access:** Local tools.

## Supported functions

| Function | Use it to |
| --- | --- |
| `diagram-maker` | Choose a suitable diagram for the relationship being explained |

## Workflow

1. Choose a diagram type based on the relationship being explained.
2. Extract only the relevant entities, connections, and boundaries from the source.
3. Lay out the diagram with readable labels and a clear visual hierarchy.
4. Check each relationship against the source and export the editable form.

## What you get

- Editable system diagram
- Rendered export

## Check the result

- Every shown relationship is supported by the source.
- The diagram remains readable at its intended size.
