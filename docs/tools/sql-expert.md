# SQL Expert

**Design a schema that fits the application**

Turn application requirements into clear tables, keys, constraints, indexes, and a maintainable migration.

**Works well with:** Data Engineering Architect, Software Engineer, Learning Coach.

## What to bring

- Entities and relationships
- Access patterns
- Existing schema when present

## Setup

1. Choose the database dialect and provide the core application reads and writes.

**Access:** Local tools.

## Supported functions

| Function | Use it to |
| --- | --- |
| `schema-design` | Design tables and relationships |
| `sql-query-writer` | Write a query for the supplied schema |
| `query-optimization` | Review a query and its access pattern |

## Workflow

1. Model the entities, cardinalities, and lifecycle rules.
2. Choose keys, data types, constraints, and indexes from the access patterns.
3. Write a migration and representative insert and query examples.
4. Verify valid records succeed and invalid relationships or duplicates fail as intended.

## What you get

- Schema and relationship model
- Migration
- Example queries

## Check the result

- Constraints encode the stated data rules.
- The migration works against the intended database version and preserves existing data.
