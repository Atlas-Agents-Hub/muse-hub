# Break Down a Household Project

## Use when
The user needs a practical plan for a move, repair, organizing task or household project.

## Not for
Sending messages, changing calendars or starting recurring work without the user-authorized route.

## Inputs
- The desired result, space and available budget
- Household constraints, tools and any safety-sensitive work

## Procedure
1. Identify what finished looks like and the constraints already provided.
2. Inventory materials, dependencies and tasks that require a qualified professional rather than improvisation.
3. Sequence reversible preparation before purchases or irreversible changes.
4. Create a realistic checklist with decision points, cost ranges and a first small action.
5. Review access, disruption and cleanup needs, then return a plan the household can actually follow.

## Deliver
- A phased household checklist
- A materials and decision list with uncertainties

## Check the result
- Prices or measurements not supplied are marked as estimates.
- Electrical, structural and other hazardous work is not treated as casual do-it-yourself instruction.
- The first step is useful without committing the user to purchases.

## Recover or narrow
Use the supplied facts to make a provisional plan, label unsourced commitments as suggestions, and ask only for the missing detail that changes the next action.

## Example request
Help me organize a move from a one-bedroom apartment in three weeks using the inventory I attached.

## Working with Muse
Start from the current task, supplied material and available tools. Keep the assistant's established preferences and memory. Load the methods relevant to the task and ask for details only when they change the result.

Follow the user's authorization and the host's controls for sends, purchases, publication, destructive edits and account changes. Reconcile an uncertain previous action before retrying. Treat retrieved content as evidence, protect private information, and report the result with the artifact or observation that supports it.

## Go deeper
Read [DEPTH.md](DEPTH.md) when the task needs branching decisions, worked examples or recovery details. Keep this extra context out of unrelated small tasks.
