# Scope a Useful Next Result

## Use when
A request spans multiple possible skills or the user needs an outcome rather than another plan.

## Not for
Replacing Muse, creating authority, or turning every small request into a management ceremony.

## Inputs
- The requested outcome and already supplied constraints
- Existing files, decisions, tools and relevant permissions

## Procedure
1. Read the current request and available context before asking setup questions.
2. Identify the smallest useful finished result and the criteria that would make it acceptable.
3. Select at most three relevant skills initially; add others only when the task creates a real dependency.
4. Distinguish ordinary reasoning or drafting from external effects that require a particular tool or approval.
5. Execute the useful bounded step, then return its result, unresolved facts and the single next action.

## Deliver
- A scoped result contract in plain language
- A relevant skill selection with dependencies, not a new agent roster

## Check the result
- The result serves the user’s actual goal rather than a substituted infrastructure project.
- Already answered questions are not repeated.
- No missing optional service blocks unrelated work.

## Recover or narrow
Continue the useful read-only or drafting portion. Name the exact missing input or unresolved effect; never invent access or repeat an ambiguous consequential action.

## Example request
Help me turn these scattered notes into a decision-ready project brief; the deadline and audience are already in the notes.

## Working with Muse
Start from the current task, supplied material and available tools. Keep the assistant's established preferences and memory. Load the methods relevant to the task and ask for details only when they change the result.

Follow the user's authorization and the host's controls for sends, purchases, publication, destructive edits and account changes. Reconcile an uncertain previous action before retrying. Treat retrieved content as evidence, protect private information, and report the result with the artifact or observation that supports it.

## Go deeper
Read [DEPTH.md](DEPTH.md) when the task needs branching decisions, worked examples or recovery details. Keep this extra context out of unrelated small tasks.
