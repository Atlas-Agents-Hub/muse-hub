# Review Against the Actual Brief

## Use when
A draft, analysis or artifact needs a focused quality pass before it is used.

## Not for
Replacing Muse, creating authority, or turning every small request into a management ceremony.

## Inputs
- The original brief and acceptance criteria
- The actual candidate artifact, not only its author’s summary

## Procedure
1. Restate the material acceptance criteria without adding unrelated standards.
2. Inspect the candidate directly and choose one representative success case and one plausible failure case.
3. Separate correctness, usefulness, presentation and side-effect risks so one green check cannot hide another failure.
4. Make or request the smallest correction that addresses a reproduced defect; cap the review to the agreed scope.
5. Recheck the changed part and report what was observed, what remains uncertain and whether a genuinely independent reviewer participated.

## Deliver
- A short prioritized review with concrete locations
- A corrected artifact or bounded revision request

## Check the result
- Every blocking finding changes the user’s outcome or a real requirement.
- The review does not claim independence merely because the same model changed roles.
- Passing structural checks is not described as proof of task quality.

## Recover or narrow
Continue the useful read-only or drafting portion. Name the exact missing input or unresolved effect; never invent access or repeat an ambiguous consequential action.

## Example request
Review this itinerary against our budget and accessibility requirements; identify only problems that could affect the trip.

## Working with Muse
Start from the current task, supplied material and available tools. Keep the assistant's established preferences and memory. Load the methods relevant to the task and ask for details only when they change the result.

Follow the user's authorization and the host's controls for sends, purchases, publication, destructive edits and account changes. Reconcile an uncertain previous action before retrying. Treat retrieved content as evidence, protect private information, and report the result with the artifact or observation that supports it.

## Go deeper
Read [DEPTH.md](DEPTH.md) when the task needs branching decisions, worked examples or recovery details. Keep this extra context out of unrelated small tasks.
